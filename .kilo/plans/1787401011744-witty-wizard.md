# Fix duplicate `/sites` prefix on property routes (404 Not Found)

## Problem
The frontend calls `POST https://api-client.promotiem.dpdns.org/sites/muot-spa/properties`
and receives `404 Not Found`.

Root cause: an uncommitted change in `app/interface/routes/__init__.py` added
`prefix="/sites"` when mounting `property_router`:

```python
router.include_router(property_router, prefix="/sites", tags=["property"])
```

But the route decorators in `app/interface/routes/property.py` already declare the
**full** paths (`/sites/{site_id}/properties` for create/list, and
`/properties/{property_id}` for get/update/delete). The extra router prefix turns them
into `/sites/sites/{site_id}/properties` and `/sites/properties/{property_id}`, which
do not match the frontend's requests nor the existing integration tests
(`tests/integration/test_property_routes.py` expects `/sites/s1/properties` and
`/properties/p1`).

Note: the sibling `public_property_router` correctly keeps `prefix="/public"` because its
decorators are written as `/sites/{site_id}/properties` (full path after the `/public`
prefix → `/public/sites/{site_id}/properties`), which matches the documented public API.

## Fix
In `app/interface/routes/__init__.py`, remove the erroneous `prefix="/sites"` from the
`property_router` include so it matches the previously working registered state:

```python
router.include_router(property_router, tags=["property"])
router.include_router(public_property_router, prefix="/public", tags=["property", "public"])
```

No changes needed in `property.py` — its decorator paths are already correct full paths.

## Verification
- Run the property integration tests: they expect `/sites/{site_id}/properties` and
  `/properties/{property_id}`, which will now resolve.
- Confirm OpenAPI docs (`/docs`) list the routes without the duplicate `/sites` segment.
- Confirm the actual request `POST /sites/muot-spa/properties` returns 200/201 instead of 404.
